Try ui-consistency

Design-Driven Development for your coding agent. What the user sees drives the code, so the page comes out right the first time instead of getting corrected in review. Your design system exists whether or not anybody drew it — this reads it before writing.

Node 20+ No build step github.com/kamenkurtev/ui-consistency

What it actually does

Before your agent builds or changes a page, it reads the page you name as the reference — top to bottom, then left to right: the holders, the components in each, how each is written, how forms validate and errors are shown — and searches how the other pages reuse those pieces. It turns that into a short checklist for the task: your page's own structure as questions, in the order the page is read.

Then each page is written from that list, one at a time, and a separate agent walks it — after first proving it catches a difference planted on purpose.

Where your project disagrees with itself, it decides by a written order and tells you what settled it, with the numbers. It does not interrogate you, it leaves no files behind to keep in step, and it writes no tests: your planning process, your tests and your logic stay yours. No script, no API key, nothing to configure.

Install it

  1. 01

    Add the marketplace and install

    In Claude Code:

    /plugin marketplace add kamenkurtev/ui-consistency
/plugin install ui-consistency@kkurtev-plugins

    Gemini CLI, Codex and Cursor have manifests too — see the README.

  2. 02

    Ask for a page, a feature or a refactor

    That is the whole setup. The agent picks up the skills on its own: it finds the pattern, plans one page per task, implements from the checklist and verifies each page. With superpowers installed, the same phases add to its brainstorming and its plan instead of running a second one.

  3. 03

    Read what it decided

    Every line of the checklist carries how, not whether — the piece your project shares, how it is written, and what settled it. Where it could only sample, or could not read something, it says so.

The skills

The agent uses them on its own; you can also invoke any of them by name.

ui-consistency:finding-patternshow pages of this kind are built here
ui-consistency:planningone checkable task per page
ui-consistency:implementingone page at a time, from the checklist
ui-consistency:verifyinga separate agent compares each page with the reference
ui-consistency:accessibilitycan it be read, can it be used without a mouse

When you report back

Keep the numbers and drop the names. Rename every component, page, route file and test-id prefix to a neutral equivalent of the same shape — OrdersGrid for a PascalCase grid, app-orders-grid for its selector form.

Reporting something

  • Say what you asked the agent, what it did, and what you expected.
  • Paste the checklist it produced, with names made neutral, and what it said it could not read.
  • Issues go to the tracker.
